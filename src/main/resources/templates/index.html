Overview

The Sanaspace application is a Spring Boot RESTful API designed to manage hospital data such as doctors, patients, medications, prescriptions, visits, and insurance. It features a console UI for interactive use.

Object-Oriented Programming (OOP) Principles

🔒 Encapsulation

  • Private fields in entities like Doctor, Patient are accessed via Lombok-generated getters/setters.
  • LoggerUtil encapsulates logging logic so other classes don’t handle it directly.
  • EntityLookup wraps entity-specific behavior like displaying and fetching records.

🧱 Abstraction

  • Controllers hide database operations behind HTTP endpoints.
  • Services abstract business rules from controllers.
  • ConsoleUI hides console input/output formatting and emoji handling.
  • EntityLookup abstracts selection logic across entities.

🧬 Inheritance

  • All repositories extend JpaRepository, inheriting CRUD methods.
  • Custom exceptions extend RuntimeException for reusable error types.
  • ServiceRouter implements CommandLineRunner to hook into Spring Boot lifecycle.

🔄 Polymorphism

  • Generic repository methods work on any entity type.
  • ApiResponseUtil handles success/error responses generically.
  • EntityLookup uses generic typing to work with multiple entity types.
  • handleOperation() accepts functional interfaces like SupplierWithException.

Models (Entities)

The models represent core data structures persisted in MariaDB:

  • Doctor: firstName, lastName, email, specialization, experience
  • Insurance: companyName, address, phoneNumber
  • Medication: name, sideEffects, benefits
  • Patient: firstName, lastName, email, phoneNumber, optional insurance
  • Prescription: links patient, doctor, medication
  • Visit: represents patient-doctor visit with composite key

Controllers

Handle HTTP requests and map them to service layer operations:

  • CDoctor: Manages doctor-related endpoints
  • CPatient: Manages patient-related endpoints
  • CMedication: Manages medication-related endpoints
  • CInsurance: Manages insurance-related endpoints
  • CPrescription: Manages prescription-related endpoints
  • CVisit: Manages visit-related endpoints
  • CAnalytics: Provides dashboard statistics

Database Schema

The application uses a MariaDB database with the following tables:

  • doctors: Stores doctor details
  • insurances: Stores insurance company details
  • medications: Stores medication details
  • patients: Stores patient details
  • prescriptions: Stores prescription details
  • visits: Stores visit details with composite keys

🏗️ Constructor Usage

Constructors ensure objects are initialized correctly with required dependencies and state.

  • ConsoleUI(LoggerUtil logger): Ensures logging is available before rendering UI elements.
  • EntityLookup(String entityName, Function> fetchPage, Function displayName): Injects dynamic behavior for each entity type.
  • ServiceRouter(SDoctor doctorService, SPatient patientService, ConsoleUI consoleUI, LookupManager lookupManager): Ensures all services are ready at app startup.
